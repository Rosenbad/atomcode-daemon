## 🚀 核心玩法：三大路线，硬核打榜

本次共创月分为三大贡献路线，开发者可自由选择参与：

* **🐛 路线一：Bug 追踪 (Bug Hunter)**
  在各种极端或日常场景下疯狂测试 AtomCode，挖掘潜在的 Bug 并提供清晰的复现路径。你就是我们的终极质检员！
* **💡 路线二：体验反馈 (Experience Officer)**
  深度体验 AtomCode，针对基础功能使用、提示词 (Prompt) 响应准确度、交互逻辑等方面，提出你的建设性优化意见。
* **🏗️ 路线三：创新架构师 (Innovative Architect)**
  **进阶挑战！** 针对 AtomCode 的底层架构、功能扩展（如新语言支持、特定框架适配）、产品迭代方向提出深度洞察，并直接提交高价值 PR！

## 📝 参赛规则与提交流程（必看！）

为了确保你的每一分贡献都能被精准记录，请务必遵循以下提交规范：

1. **标签护体：** 在代码仓提交 Issue、PR 或参与讨论区发布内容时，标题必须带上 **`[共创大赛]`** 专属标签（例如：`[共创大赛] 修复了在使用 XXX 框架时的上下文截断问题`）。未带标签的提交将无法计入打榜统计！
2. **真实有效：** 提交的 Bug 必须可复现，反馈建议必须具体且有实操性。无意义的灌水内容将被视为无效。
3. **规范完整：** 提倡使用仓库提供的 Issue/PR 模板。信息填写越完整、图文详实、复现代码清晰，获得的评分越高。
4. **价值导向：** 官方评审团将依据产品价值赋分，**直接提交高质量 PR (Pull Request) 的开发者将获得最高权重加分！**
